# pop'n music リザルト整形ツール

e-amusementアプリのプレイシェア機能で表示された、pop'n musicのゲームリザルト画面のスクリーンショットを、SNS投稿しやすい形に加工するための静的Webアプリです。ビルド不要の素のHTML/CSS/JavaScriptで作られており、GitHub Pagesでそのまま公開できます。すべての画像処理はブラウザ内(Canvas API)で完結し、画像が外部サーバーに送信されることはありません。

## 機能
- スクリーンショットに写り込むスマホの上部メニューなど機種依存の余白を、色の均一性から**自動検出してトリミング**(必須機能・操作不要)
- オプションで、判定内訳の一部(BAD・COMBOなど)の位置を移動して見やすく並べ替え(画像の大部分は元のまま、一部の要素だけを移動する)
- オプションでプレイ日付・ユーザー名を単色塗りつぶしで非表示化
- オプションで画像左下に小さくツール名の透かしを表示(デフォルトON、チェックを外せば非表示)
- 複数枚のリザルトを枚数可変の自動グリッドで1枚に集約(SNS投稿用)。各画像は縮小せず原寸のまま配置される。並べ替えの有無に関わらず利用可能。画像の追加・削除やオプション変更のたびに自動で更新される
- オプションで個々の加工結果画像の表示/非表示を切り替え(デフォルトON)。集約画像だけ欲しい場合はOFFにすると個別のカード一覧が非表示になる(集約画像には影響しない)
- オプションの設定はブラウザの`localStorage`に保存され、次回アクセス時にも同じ設定が復元される(サーバーには送信されない)

## 使い方
1. `index.html` をブラウザで開く(ローカルでも `file://` でそのまま動作します)
2. 「ファイルを選択」またはドラッグ&ドロップでリザルト画像を追加(余白の自動トリミングは自動で行われます)
3. 必要に応じて「判定内訳を見やすく並べ替える」「プレイ日付を隠す」「ユーザー名を隠す」「ツール名の透かし表示」「個別の加工結果画像を表示」のチェックを切り替え
4. 個別表示ONの場合、各画像はダウンロードボタンで個別に保存可能
5. 画像を追加すると自動的に集約画像(まとめ画像)も生成されるので、ダウンロードリンクから保存

## GitHub Pagesへの公開手順
1. このリポジトリをGitHubにpush
2. リポジトリの Settings → Pages で、公開元ブランチ(例: `main`)とルートディレクトリを指定
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

## ファイル構成
```
index.html            UI本体
css/style.css         スタイル
js/layoutConfig.js    余白自動検出のパラメータ、マスク・要素移動・透かしの定義(比率ベース)
js/imageProcessor.js  1枚のリザルト画像に対する自動トリミング・プライバシーマスク・要素の位置移動・透かし表示
js/collage.js         複数の加工済み画像を、縮小せず自動グリッドで1枚に集約
js/main.js            UIイベント制御・状態管理
samples/               動作確認用のサンプル画像を置く場所
```

## 余白の自動トリミングについて
pop'n musicのリザルト画面本体は彩度の高い色使いなのに対し、スマホの余白(ステータスバー・戻るボタン・決定ボタンの周りなど)は無彩色(グレー系)であることを利用し、画像の各行を「無彩色画素が多い行(余白)」と「そうでない行(本体)」に分類したうえで、本体行が最も長く連続する区間を自動的に採用します。ステータスバーのアイコンや、余白の途中にある孤立した色つきボタンに惑わされないよう、単純な端からの均一色判定ではなく「最長区間」を採用している点がポイントです。この判定は `js/layoutConfig.js` の `edgeDetection` パラメータで調整できます。

- `saturationThreshold`: RGB最大値と最小値の差がこれ以下なら「無彩色(余白側)」とみなす
- `greyRowThreshold`: 1行のうち無彩色画素の割合がこれ以上なら「余白行」とみなす
- `sampleStride`: 各行を何画素おきにサンプリングするか(処理速度と精度のトレードオフ)

機種・スクリーンショットの撮り方によっては本体を正しく検出できない場合があります。実際のスクリーンショットで動作確認をしながら、必要に応じてこれらの値を調整してください。

## マスク・並べ替え座標のキャリブレーションについて
`js/layoutConfig.js` の `regions`(マスク対象の座標)と `layoutMoves`(並べ替えで移動する要素の座標)は、`samples/sample1.png` を実測して設定した値です。別の機種・解像度のスクリーンショットで大きくズレる場合は、追加のサンプルを見ながら以下を調整してください。

- `regions[].rect`: 自動トリミング後の画像内での、プレイ日付・ユーザー名の位置(比率)。マスクオプションで使用
- `layoutMoves[].from` / `.to`: 並べ替えオプションON時に移動する要素の「移動元」「移動先」の位置(比率)。画像のそれ以外の部分は変更されない

座標はすべて `0.0〜1.0` の比率で指定します(絶対ピクセルではありません)。これはスマートフォンの機種によってスクリーンショットの解像度が異なるための対応です。ただし、機種によって画面のアスペクト比自体が大きく異なる場合は、比率だけでは吸収しきれない可能性があるため、その場合はサンプル画像を確認しながら追加の調整が必要になります。
